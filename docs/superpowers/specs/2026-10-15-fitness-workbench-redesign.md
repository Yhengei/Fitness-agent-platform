# 健身多 Agent 工作台前端重构设计

## 目标

将现有前端从信息密度偏高、结果不醒目的单页面板，重构为适合个人健身决策的工作台。保留当前 API 和 Agent 流程，只改变信息架构、视觉层级、状态呈现和页面内导航。

## 信息架构

- **今日记录**：左侧固定表单，录入每日状态、训练完成情况、动作和训练约束。
- **当前计划**：右侧首要结果区，展示最终计划的状态、核心建议、动作清单和安全提醒。
- **Agent 分析**：右侧中部，按 Agent 顺序展示运行进度。每个 Agent 显示状态、简短结论和可展开的结构化证据。
- **周报与学习**：右侧下部，独立展示周期指标、建议和 Learning Agent 提案。
- **运行状态**：顶部显示模型提供方、模型名称和云端/本地状态；不让运行元信息抢夺训练结论的注意力。

## 交互

- 顶部提供页面内锚点导航：今日记录、当前计划、Agent 分析、周报。
- 提交后右侧按事件流实时更新 Agent 状态；运行完成后滚动到当前计划锚点。
- 最终计划采用高对比摘要卡，明确分出“今天做什么”“为什么这样安排”“安全提醒”。
- Agent 过程默认展示清晰的一句话结论，JSON 和证据作为折叠详情保留。
- 空状态、运行中、完成、失败和风险停止均有独立视觉状态。
- 移动端保持单列顺序：当前计划、今日记录、Agent 分析、周报，避免结果被表单推到页面底部。

## 视觉系统

- 主题为“温暖健身工作台”：深墨绿用于导航和主要操作，暖白用于阅读区域，浅鼠尾草色用于分组背景，珊瑚色只用于疼痛/风险提醒。
- 取消低对比度小字作为主要结果载体。标题、结论、训练动作和风险提示使用更高字号、字重和对比度。
- 卡片圆角保持克制（不超过 10px），阴影轻量，避免营销页式大卡片堆叠。
- 采用稳定的网格和固定状态条高度，避免 Agent 输出更新造成页面跳动。

## 实现边界

- 不修改后端 API、数据模型、事件协议或模型供应商逻辑。
- 不增加多人账号、认证、支付或新的业务流程。
- 复用现有 `App.tsx` 数据请求和 EventSource；新增展示组件/辅助函数可以留在前端模块内，避免无必要的工程拆分。
- 构建验证使用现有 `npm run build`。
